# Пакет города

Город — это папка `content/cities/<id>/` из четырёх файлов. Город попадает в приложение,
только если указан в `content/cities.json` и проходит проверку `npm run content:check`.
Формат описан кодом в `src/content/schema.ts`. Если этот документ и код расходятся, прав код.

```
content/
  cities.json                 порядок городов в списке
  cities/troitsk/
    city.json                 город: название, регион, центр, район карты, вступление
    places.json               объекты: рассказ, даты, люди, источники, фото
    routes.json               маршруты: порядок объектов
    lexicon.json              словарь озвучки: инициалы, сокращения, ударения (необязательный)
    walking.json              поправки к пешеходному графу после прохода на месте (необязательный)
    streets.json              граф улиц — строит workflow Streets, руками не править
    photos/                   фото с правами (появятся позже)
public/
  map/<город>/                своя подложка карты — строит workflow Map
  audio/<город>/              озвучка рассказов — пишет workflow Voice; manifest.json — с какого текста
```

## Статусы

У города, объекта и маршрута есть поле `status`:

| Статус | В приложении | Что требуется |
|---|---|---|
| `draft` | не показывается | только правильный формат |
| `review` | показывается | формат; без источников — предупреждение |
| `published` | показывается | ≥ 1 источник, `editorial.fact_checked_by`, пустой `editorial.todo` |

Объект нельзя опубликовать без источников и без отметки о том, кто проверил факты: проверка остановит сборку.

## Объект (`places.json`)

| Поле | Обязательно | Что это |
|---|---|---|
| `id` | да | постоянный идентификатор латиницей (`passazh-yaushevykh`). Попадает в адреса и QR-коды и **не меняется** |
| `name`, `category`, `address` | да | категории: `architecture`, `religion`, `history`, `monument`, `museum`, `public-space`, `nature` |
| `location` | да | координата объекта |
| `listen_at` | нет | где встать слушать, если не у самого объекта (вход, сквер напротив). По этой точке засчитывается прибытие |
| `arrival_radius_m` | нет | свой радиус прибытия (15–150 м) для площадей и больших объектов |
| `summary` | да | одна строка для списков, до 160 знаков |
| `story` | да | основной рассказ абзацами. Его озвучиваем у объекта |
| `note` | нет | короткая заметка на 30–60 с для «свободной прогулки» |
| `dates` | нет | `{ "date": "1908/1910", "event": "Строительство" }`. Форматы даты: `1866`, `1754-05`, `1743-05-22`, `1908/1910`, `XVIII` |
| `people` | нет | `{ "name", "role", "years"?, "attribution"? }`. Роли: `architect`, `sculptor`, `artist`, `engineer`, `customer`, `founder`, `subject`. `"attribution": "probable"` — «предположительно» |
| `heritage` | нет | `{ "level": "federal" \| "regional" \| "local" \| "identified", "registry_id"? }` |
| `sources` | для `published` | `{ "title", "url"?, "publisher"?, "year"? }` |
| `photos` | нет | `src` — путь от `public/` (`photos/<город>/<id>.jpg`); обязательны `author` и `license`, иначе проверка не пройдёт. Первое фото — обложка места в плитке и карточке. `focus` (например `"50% 20%"`) — какую часть кадра держать в центре при обрезке: для вертикальных снимков, чтобы не срезались головы |
| `then_now` | нет | «было/стало»: архивное и современное фото и точка съёмки |
| `editorial` | нет | для редакции, в приложение не попадает: `location_source`, `todo`, `fact_checked_by`, `fact_checked_on` |

## Маршрут (`routes.json`)

`id`, `status`, `title`, `description`, `stops` — список `id` объектов по порядку.
`duration_min` — длительность, если её задаёт редакция. Иначе её оценивает сборка:
длина пути по улицам, шаг 4,2 км/ч, время рассказов и по 2 минуты на остановку.

Путь между соседними остановками сборка прокладывает по графу улиц (`streets.json`), тем же
алгоритмом, что телефон во время прогулки. Если точка дальше 150 м от улиц — ошибка;
если путь в 4 раза длиннее прямой — предупреждение (вероятно, в OSM не хватает дорожки).

## Пешеходные поправки (`walking.json`)

После прохода маршрута на месте: `walk_areas` — скверы, по дорожкам которых ведём, даже если
в OSM они не отмечены; `manual_paths` — дорожки, которых нет в OSM; `leg_via` — через какие точки
идёт участок между двумя объектами (`{ "from", "to", "via": [[широта, долгота]] }`).
После правки workflow Streets сам пересоберёт граф.

## Словарь озвучки (`lexicon.json`)

`entries`: `{ "text": "И. И. Неплюев", "say": "Иван Иванович Неплюев" }` меняет написание только
в тексте, который уходит в синтез речи. Длинные записи применяются раньше коротких.
`stress`: `{ "word": "Троицк(\\w*)", "say": "тр+оицк\\1" }` — ударение знаком `+` перед ударной
гласной (формат Яндекс SpeechKit); слово ищется целиком, регистр сохраняется.
Общие для всех городов правила (века римскими цифрами) и фразы навигатора — `content/voice.json`.
Если записи нет ни в одном тексте, проверка выдаст предупреждение: скорее всего, это опечатка.

Озвучивается «Название. Рассказ». Сборка сравнивает хэш этого текста с `public/audio/<город>/manifest.json`
и предупреждает, если текст поменяли после озвучки.

## Как добавить город

1. Создать `content/cities/<id>/` по образцу Троицка и добавить `id` в `content/cities.json`.
2. `bbox` — квадрат примерно 20 × 20 км вокруг центра. На этот район строятся карта и пешеходный граф.
   Все объекты должны быть внутри него.
3. Actions → **Map** (город `<id>`) и **Streets** — своя карта и граф улиц.
4. Начать со статуса `review`. Запустить `npm run content` — отчёт покажет, чего не хватает.
5. Actions → **Voice** → `missing` — озвучка рассказов.
6. Пройти маршруты на месте: поправить `location`, `listen_at` и `walking.json`, записать
   в `editorial.location_source`, что координата проверена.
7. После фактчекинга перевести объекты в `published`.

Что делает сборка (`tools/build-content.ts`): проверяет всё вышеописанное, убирает черновики
и редакционные поля и пишет `public/data/<город>.<хэш>.json` и `public/data/cities.json`.
Хэш в имени файла меняется с каждой правкой текста, поэтому телефоны не застревают на старой версии.
